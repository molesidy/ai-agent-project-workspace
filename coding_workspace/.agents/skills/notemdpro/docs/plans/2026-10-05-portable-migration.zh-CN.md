# 可移植 Markdown 工具与工作流契约

## 基线与决策

来源：Obsidian NotEMD 1.9.12，提交 `0f493b8d3cd60553e5a517660ca1a729ce4acdfc`。本仓库是包含两个 TypeScript 可执行工具的指令包，不是 Obsidian 插件或渲染宿主。

原公式工具导入了 Obsidian 和两个不存在的本地模块。Mermaid 修复在确认图表无效之前就删除标点，旧技能说明还引用了不存在的插件文件与测试。因此本次迁移同时修复可执行入口和能力说明。

## 实现归属

- `scripts/markdown.ts` 统一处理围栏长度与标记匹配、嵌套示例、YAML、缩进代码和行内代码保护。公式与 Mermaid 操作共享该边界。
- `scripts/markdown-file.ts` 严格解码 UTF-8，同时保留 BOM。非法字节在写入前触发错误。
- `formulaFixer.ts` 只转换保护区域之外成对的独立美元分隔符。文件先在源文件旁暂存，重新读取核对后替换；无变化文件保留修改时间。拒绝只读文件。批处理分别报告修改数、处理数、取消与逐文件错误，不跟随符号链接文件。
- `mermaidProcessor.ts` 先用 Mermaid 11.17.2 验证，有效图表逐字节保持不变。自动路径只修复完整且无歧义的纯 ID `--|>` 边，再次解析后才接受。其他语法错误及未知/未来类型保留原文并明确报告。旧字符串函数导出保留，供显式审阅使用。
- CLI 入口提供 JSDOM 解析环境，不需要浏览器或 Obsidian。所有图表检查通过后才写入新文件，并拒绝覆盖已有输出。
- 新增 diagram-generator 与 workflow-runner 技能，要求保留有原文依据的节点/关系，区分层级与谓词，保留完整任务日志，默认显示错误详情。这些是宿主执行契约，不代表新增了渲染器或任务引擎。

## 复核发现与回归预防

解析成功不等于语义不变：初版迁移仍把无效流程图送入旧的全局改写链，单条错误边会连带改变有效标签的标点。最终自动路径已不再调用该规则链。

新增测试还复现了跨行代码被当作公式、缩进代码被改动，以及非法 UTF-8 字节被替换为 U+FFFD。共享扫描器和严格文件读取边界已覆盖这些情况。这也是不能整体照搬旧源工具的原因。

扫描器随文档长度线性处理。修复逐个验证拥有的 Mermaid 块，并从后向前替换，以保持前面块的偏移位置。该工具面向笔记规模文档，不宣称具备无限规模的流式解析能力。

## 兼容性与迁移

保留字符串形式的公式/Mermaid API。原先不可用的 Obsidian 文件 API 改为 `fixFormulaFormatsInFile(path, reporter?)` 和 `batchFixFormulaFormatsInFolder(path, reporter?)`；Obsidian 调用方需自行提供宿主适配。验证过的工具链要求 Node >=22.19。

单独安装技能只提供指令；执行共享工具需要完整检出并运行 `npm ci`。根目录历史 TODO/analysis 文档记录较早工作，其中关于完全消除宿主耦合和必须先运行全局正则的结论，以本报告为准。

本次未增加提供商、翻译服务、知识索引、SVG/PDF 引擎或预览 UI。宿主缺少导出能力时必须明确报告，保留源产物，并验证真实输出，不能仅把文件改名为 PDF。诊断折叠属于具备界面能力的宿主的呈现策略。

## 验证与交付

- `npm test`：11 项通过，覆盖真实 Mermaid 解析、成功的保守修复、语义保留、Markdown 保护、BOM/CRLF、严格 UTF-8、无变化不写入、取消及可执行 CLI。
- `npm run typecheck`：通过。
- 新增内容保真回归在修复前失败，最终修复后通过。
- GitHub 验证在 Linux/Windows、Node 22.19 上执行相同检查。
- 未调用真实 LLM、翻译 API、LM Studio 或界面自动化。全部中英文文档由主助手直接编写。
